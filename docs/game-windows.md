# 游戏与自绘窗口

版本 0.1.2 的游戏路径使用真实 Win32 窗口身份、截图和扫描码按键，不要求游戏提供可编辑的 UI Automation 控件。无标题窗口仍可通过进程名称被发现。

1. 请求 `computer_use_find_window({query:"杀戮尖塔2"})`。也可按返回的实际英文标题或进程名搜索。内置中文搜索别名只是检索提示，不是权限规则。
2. 候选多于一个时，核对 `title`、`process_name`、`class_name` 和真实 `app`，选择返回的 `Window`。不要使用 Steam AppID、PID、进程目录猜 HWND。
3. 没有候选时，插件不会假装取得窗口。请用户启动游戏并保持窗口可见；不能改权限、启动终端或另造 helper 来恢复发现。窗口可见但仍无法绑定时，交由用户检查进程权限和桌面会话。
4. 用 `get_window_state` 请求 `include_text:false`、`include_screenshot:true`；弱 UIA 游戏无需读取文本树。按原始截图尺寸选择坐标，执行一次点击并检查刷新状态。
5. 游戏按键使用 `press_key` 的 `mode:"scan-code"`；字母键也以物理扫描码处理。无 Win32 焦点句柄的自绘窗口仅在最近一次已验证点击、目标前台/身份/几何不变时允许该路径，不允许盲发文字。系统快捷键、密码输入和超出窗口的输入仍拒绝。
6. 检查回执和画面实际变化。`queued_unverified` 只证明排队；无可见效果不要连续重复相同输入。错误中的恢复说明决定下一步，`INPUT_PAUSED` 不能由模型自行解锁。

插件不承诺支持任意游戏的 Raw Input、反作弊或独占全屏过滤机制。窗口化/无边框模式是否合适由用户决定，不由模型自动改系统设置。模型还需要可接收图像的路由，才能理解游戏画面。

本次回归通过自建无标题/自绘/扫描码/文本过滤测试窗验证这些路径；《杀戮尖塔 2》本体是否已实测，以最新验证记录为准。
