# 0.1.3 审批策略

默认 `approvalMode: risk` 用于自主完成普通电脑任务，不再对每次点击提问。

| 行为 | risk 模式 |
|---|---|
| 枚举、搜索、读取窗口截图/UIA | 不请求审批 |
| 启动 Steam 等普通应用、激活窗口 | 不请求审批 |
| 游戏库导航、搜索、滚动、游戏按键 | 说明本次输入意图后，不请求审批 |
| 购买/支付、删除、发送、上传、共享、权限变更、敏感信息 | 每次请求审批 |
| 缺少动作意图、没有当前绑定观察、明确不确定影响 | 请求审批或参数错误；不盲发 |
| 终端、密码控件、系统键、权限不兼容、已暂停输入 | 原有拒绝规则继续生效，批准不解除 |

模型输入工具携带 `intent`，描述**这一动作**的目的及实际影响，例如“打开 Steam 游戏库”“确认购买游戏”。可选 `risk` 直接标记高危效果；不能把购买写为 `routine` 以规避审批。插件另查同一 agent/窗口/令牌的当前观察：索引目标、坐标处控件名、焦点控件和部分删除/提交快捷键。UIA 控件值与整段文档不作为按钮含义进行扫描，避免搜索框内容制造误报。

Steam 示例：

```json
{"app":"E:\\Steam\\steam.exe"}
```

启动后的观察不需要审批。以真实观察中的窗口、索引和令牌执行普通点击：

```json
{
  "window":{"id":123,"app":"E:\\Steam\\steam.exe"},
  "observation_id":"实际最新令牌",
  "element_index":7,
  "intent":"打开 Steam 游戏库",
  "risk":"routine"
}
```

上面的路径、句柄、索引只是格式示例，必须取自真实发现结果。下单等动作应说明实际效果并用 `risk: purchase`，每个动作各批一次。高危批准不会保存为应用免审权限；`trustedApps` 在 risk 模式中也不能免除它。

## 现有 profile 升级

先安装 0.1.3 或使用已构建的源码链接，再在当前 profile 的 cpuse 配置中设置：

```yaml
- id: cpuse
  name: dsh-plugin-cpuse
  config:
    approvalMode: risk
```

保留你的其他配置，只改这一项，然后重载插件或重启 DSH。旧 profile 显式写着 `approvalMode: always` 时，升级不会擅自覆盖这个选择；仅使用 schema 的新默认值不能改变旧的显式值。

Harness 的 `ask` 策略会把高危请求交给审批界面；`never` 拒绝高危请求，`always` 可自动批准。插件不改宿主会话策略，也不覆盖上游明确拒绝；因此上游针对所有工具的审批门仍可能产生额外请求。没有审批服务时普通操作可执行，高危操作失败。

## 判断范围

这是意图和控件提示的保守规则，**不是通用视觉风险识别器**。纯画布、错误 UIA 名称、模糊或错误意图可能导致漏判或误判；同一坐标上的异步界面变化也无法完全排除。模型必须看真实界面、如实说明效果，影响不明时停下确认，不能把界面内容当作授权。高危申请拒绝/取消后不会自动重试或切换工具执行。

风险审批适用于 Harness 工具及其 Code Mode SDK 调用；可信本地 JS facade 没有宿主审批服务，调用者承担用户授权责任。
