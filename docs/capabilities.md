# 能力覆盖与边界

本项目面向 DeepSeek Harness **0.2.0-rc.2**，以 Codex Computer Use 公开给模型的 `sky` window2 API 为接口参考，独立实现 Windows 桌面后端。它不分发或依赖私有 `@oai/sky` SDK、Codex helper 或 Codex 的内部通信协议。工具覆盖相同的十三类窗口操作，并增加 `capabilities` 查询及显式观测令牌。

“覆盖接口”不意味着复刻 Codex 的所有内部行为。UI Automation、Windows 的前台限制、截图接口和所选模型共同决定某个应用是否可操作。运行时返回的 `capabilities` 和工具错误是当前主机能力的依据。

| Codex window2 API | 本插件操作 | 实现方式与条件 |
|---|---|---|
| `list_apps` | 枚举应用及其窗口 | Windows 应用发现与当前可见窗口；返回的应用标识供后续调用使用 |
| `list_windows` | 枚举可操作窗口 | Win32 窗口枚举；模型不能任意构造句柄选择未枚举窗口 |
| `get_window` | 重新取得窗口对象 | 只接受已经枚举的窗口 ID，重新核实所属应用 |
| `launch_app` | 启动应用 | 已发现应用标识或明确的可执行文件路径；使用进程 API，不解释 shell 命令 |
| `get_window_state` | 观察窗口 | UI Automation 树、文本、焦点/选择状态与 PNG 截图；返回新的 `observation_id` |
| `click` | 元素或坐标点击 | 最新 UIA 元素索引，或最新截图内坐标；鼠标输入会核实前台目标 |
| `press_key` | 单键与组合键 | `SendInput`；支持的键名由后端解析；系统键组合受限制 |
| `type_text` | 输入文本 | Unicode 输入；内容作为数据传递，换行等字符不作为 shell 代码解释 |
| `scroll` | 横向/纵向滚动 | 最新截图内的起始坐标与滚动增量 |
| `set_value` | 替换可编辑控件值 | UI Automation ValuePattern；不支持该模式的元素明确报错 |
| `drag` | 拖动 | 同一最新截图内的起止坐标，`SendInput` 分段移动 |
| `perform_secondary_action` | 无障碍辅助动作 | 元素实际支持的 UIA 模式；使用观察结果给出的动作名 |
| `activate_window` | 激活窗口 | Win32 前台窗口 API；Windows 拒绝时不会发送输入到其他窗口 |
| 无对应接口 | `capabilities` | 当前平台、后端、截图与输入能力诊断 |

## 观察与输入的约束

先枚举应用/窗口，选定具体窗口，再取得状态，最后执行输入。每个输入都携带该窗口最新 `observation_id`。令牌绑定调用会话，另一会话观察过相同窗口也不能代用。元素索引和 `screenshotId` 只在对应观察中有效；重新观察、输入之后或超出新鲜度期限，就需要使用新状态。

坐标以截图像素为参照，必须处于所引用截图的范围内。截图包含宽高、屏幕原点和层次信息。不能把整屏坐标直接放进窗口截图的坐标字段，也不能拿其他窗口的截图 ID 操作当前窗口。

输入完成后，控制器自动取得新的窗口状态供模型核实结果。输入交付成功只表明 Windows 接收了动作，是否达成任务仍要看新状态。自动刷新失败时，动作可能已经生效；必须重新观察后再决定下一步。

所有控制器实例共享串行队列，避免插件自身同时向桌面发送相互冲突的输入。这不是桌面独占租约：用户、其他程序及独立插件仍可能改变窗口状态。取消、超时或原生进程退出不会回滚已发送的输入，也不会自动重试。

## Windows 会话与截图

需要处于活动、已解锁的交互式 Windows 桌面会话。服务会话、无桌面的 SSH 进程、锁屏、断开的远程桌面以及权限较高的应用都可能拒绝枚举、截图或输入。Windows 的 UIPI 和前台规则不会因为安装插件而改变。

Windows.Graphics.Capture 用于按窗口捕获，可在窗口被遮挡时取得窗口内容。最小化、受保护内容、系统安全桌面和应用自身渲染行为仍可能限制截图。后端必须报告所使用的截图方式与失败原因；不能把遮挡后的屏幕区域当成目标窗口的真实截图。

`allowPrintWindowFallback` 默认关闭。明确启用后，WGC 失败可尝试 PrintWindow；返回的截图标注后端与降级原因。PrintWindow 对 GPU 渲染窗口可能不完整，不能据其成功推断 WGC 可用。

## 模型视觉与纯文本模式

截图必须经 Harness 的附件存储保存，并作为真实 `image` 内容块发送到明确支持图像输入的模型路由。向模型输出 PNG 的路径、URL 文本或 base64 字符串不会赋予模型视觉能力。

纯文本模型仍可使用 UIA 树和文本操作语义明确的控件，但无法据此可靠操作画布、图像内容、游戏、未暴露无障碍信息的自绘控件，或仅有图标的布局。`include_screenshot: false` 可显式请求仅文本观察；其结果不包含可用于坐标动作的截图身份。

## 验证声明

自动化单元测试使用假后端验证控制器的状态、校验、串行、取消与错误恢复规则。JSONL 测试验证进程通信。它们不证明所有 Windows 应用都受支持。

原生验证应在插件自建测试窗口中检查 UIA、输入和截图，避免操作用户现有应用。遮挡截图的验证需比对测试窗口的已知像素内容；前台截图成功不能代替遮挡截图验证。真实 Harness 挂载还需验证图像附件在 Session 结果中存在，并由模型路由接收。
