# 验证与问题定位

兼容性验收目标为 DeepSeek Harness **0.2.0-rc.2**，Cordis **4.0.4**、Schemastery **3.18.4**。先运行 `npm ci`，核对 `package-lock.json` 中 Harness 包均为该目标发布版本，再运行项目构建和自动化测试。原生验证在可见、已解锁的 Windows 桌面运行；自动化测试不会向用户应用发送键盘或鼠标输入。

## 分层验收

| 层次 | 应验证的行为 | 通过标准 |
|---|---|---|
| 参数边界 | 窗口句柄、坐标、键名、文本及观察令牌 | 非法参数在原生调用之前失败；输入文本保持原样 |
| 控制器 | 枚举、会话绑定、新鲜度、自动刷新 | 旧/异窗/异会话令牌被拒绝；成功输入返回新状态 |
| 串行与取消 | 多调用、多控制器、排队时取消 | 原生调用不重叠；已取消调用不开始输入；错误不自动重试 |
| 进程协议 | JSONL、分块响应、原生错误、退出、超时 | ID 匹配；任何不确定结果要求重新观察 |
| Windows 后端 | UIA、窗口截图、输入与前台确认 | 在自建测试窗中验证实际状态改变与真实像素 |
| Harness 接入 | 0.2.0-rc.2 的工具注册、附件、提示词及资源卸载 | 目标发布包的真实运行时能加载工具；PNG 成为持久化 image 附件；卸载关闭原生进程 |

## 原生测试窗口场景

测试窗口应带独特标题，包含文本框、普通按钮、可展开区域、列表选择、可滚动容器，以及已知颜色或棋盘格画布。只对该窗口执行下列动作，测试结束后自行关闭它。

1. 枚举并匹配窗口 ID/应用路径；观察 UIA 索引、文档文字、焦点、选中项和选中文字。
2. `set_value` 替换和清空文本框；`click` 激活按钮；辅助动作展开/折叠控件；通过新状态检查实际结果。
3. `type_text` 输入中文、补充平面字符和换行；用组合键选择文字；检查 UIA 暴露的文本和选择是否符合预期。
4. 对列表执行滚动与拖动，并核实列表或画布实际变化。拖动中发生错误时检查按键/鼠标按钮释放。
5. 取得截图并检查 PNG 解码尺寸、屏幕原点、DPI、多显示器负坐标，以及截图 ID 对应的坐标范围。
6. 用第二个自建测试窗遮挡目标；检查 WGC 返回的目标棋盘格仍正确。将目标最小化或关闭，核实不会返回其他窗口内容。
7. 观察后移动/关闭窗口、删除控件、改变焦点或手动操作；核实过期对象和前台失败会报错，并不会将输入交给其他应用。
8. 中断/超时发生后重新枚举与观察，再检查当前状态；测试不能通过自动重试掩盖不确定结果。

锁屏、系统安全桌面或管理员应用相关测试需要专门测试环境。常规验收不应触发这些桌面状态或操作用户应用。

## 恢复顺序

遇到 `STALE_OBSERVATION`、截图身份无效或元素已失效，重新取得窗口状态。遇到窗口关闭或所属应用改变，重新枚举再选窗。遇到 `ABORTED`、`TIMEOUT`、原生 helper 退出或输入后刷新失败，先检查当前界面是否已改变；重复点击或重新输入可能造成第二次提交。

0.1.2 中，已派发输入的未知失败会暂停该目标的对应通道，稳定权限阻断会暂停该目标的 SendInput。`INPUT_PAUSED` 不因刷新或枚举解除。模型应只观察并报告；人工完成诊断后再决定重载插件。文本的 Unicode 和 paste 共用暂停门，不能切换方法重放。游戏窗口使用搜索和截图/扫描码路径，参见 [游戏窗口指南](game-windows.md)。

无法得到截图时，查看 `capabilities`、原生错误和窗口状态。只有 UIA 内容可用的情况下，可以继续做能够用无障碍信息核实的操作。图像接纳失败时检查附件服务和模型路由声明，不能通过把 base64 放进文本绕过模型图像能力限制。

## 结果记录

记录 Windows 版本、图形会话状态、DPI/显示器布局、Node/.NET 版本、构建命令、测试通过数、实际截图后端，以及每项原生场景的通过/失败。测试记录应清楚区分“构建成功”“模拟测试通过”“自建窗口验证通过”和“真实 Harness/视觉模型联调通过”。
